\section{Experiment and Compute Provenance}
\label{app:provenance}

The supplementary artifact includes a machine-readable experiment manifest at
\path{docs/experiments/experiment_manifest/experiment_manifest.json}. It joins
\ExpProvenanceExperimentCount{} principal runs
to pinned dataset revisions, split and code digests, effective configuration, seed policy, output
digests, and the remote execution log. The measured environment provides an
\ExpComputeAccelerator{} accelerator, \ExpComputeCpuCount{} logical CPUs, and
\ExpComputeRamGiB{} GiB RAM. The MLP run takes \ExpMlpWallSeconds{} s with
\ExpMlpPeakMemoryMiB{} MiB peak resident memory; the DROID and controlled-suite processes take
\ExpDroidWallSeconds{} s and \ExpControlledWallSeconds{} s. The conversion-scale process takes
\ExpConversionScaleWallSeconds{} s with \ExpConversionScalePeakMemoryMiB{} MiB peak resident memory;
its \ExpConversionScaleFailedRunCount{} preliminary failed runs are retained with their nonzero exit
status and logs. The multi-trajectory timing audit takes \ExpTimingWallSeconds{} s with
\ExpTimingPeakMemoryMiB{} MiB peak resident memory. The logs also record storage and exit status.
Temporal ridge shares the controlled-suite process and is labeled with that accounting scope rather
than assigned invented per-subtest compute.

The anonymous supplementary ZIP is built from an explicit allowlist with deterministic entry
digests. Source-control history and local environments are excluded; text payloads are anonymized
before hashing, binary payloads are scanned, and a separate audit checks extracted PDF text and
metadata plus every ZIP path and payload.

\section{Open Gates: Commands and Acceptance Rules}
\label{app:gates}

\begin{openresult}{results not claimed in this release}
The artifact keeps unfinished claims executable instead of hiding them. The current RFC release gate
is:
\texttt{python3 tools/release\_readiness.py --strict-rfc}. The full-standard gate is:
\texttt{python3 tools/release\_readiness.py --strict-full}. The latter is expected to fail until
the two gates boxed below are backed by committed reports and, additionally, external standard
evidence exists: maintainer-reviewed diagnostics, an independently written reader/exporter, and at
least one externally published WorldEpisode-compatible dataset. The same gates are indexed in
\path{docs/experiments/open_reproduction_gates/open_reproduction_gates.json}.
\end{openresult}

\begin{openresult}{ACT/Diffusion and rollout impact}
Result: \ExpActDiffusionResult. Rollout impact: \ExpRolloutImpactResult. Scene-only leakage:
\ExpSceneOnlyLeakageResult. First replace the task-derived proxy with physical
scene/source-capture IDs and construct task-stratified random and scene-lineage-disjoint splits.
Then regenerate split packages and LeRobot job specs and run ACT/Diffusion inside a LeRobot training
environment. Before training, materialize source images or a semantically valid environment-state
feature and require the compatibility preflight to complete a training step.

Required artifacts: a proof that task support is identical across protocols and scene lineage is
disjoint, policy checkpoint digests, train/eval configs with at least five seeds, offline action
metrics, rollout traces or videos with content digests, and an updated policy-gate report.

Acceptance rule: both split protocols must preserve task support, at least one ACT or Diffusion
Policy must report both protocols over multiple seeds, and at least one simulator or physical
rollout must use the same manifests. Running the current task-confounded jobs does not close this
gate.
\end{openresult}

\begin{openresult}{famous-benchmark score-inflation proof}
Result: \ExpBenchmarkInflationResult. A targeted DROID subset rerun can be attempted with
\texttt{uv run --with pyarrow --with requests --with numpy python
tools/famous\_benchmark\_policy\_rerun.py --benchmark droid\_100 --required}. The proof contract is
then enforced with \texttt{python3 tools/benchmark\_inflation\_gate.py --required}.

Required artifacts: benchmark-specific WorldEpisode conversion, lineage/timing audit, faithful
published-protocol policy rerun, paired corrected evaluation under the same metric, and a measured
baseline-minus-corrected score drop.

Acceptance rule: the gate must contain at least one inflation-proof valid rerun report with
\texttt{measured\_inflation=true}. Source-level metadata gaps alone are evidence of missing
controls, not evidence that published scores are inflated.
\end{openresult}

\section{Dataset-Scale Audit (\texttt{DATASET.001})}
\label{app:scale}

To address production scale, we audit the dataset manifest in
\path{examples/scalable-corpus.worldepisode-dataset.json}. The audit validates
\ExpScaleNamespaceCount{} namespaces, \ExpScaleResolverCount{} resolver schemes,
\ExpScaleRegistryCount{} registries, \ExpScaleShardCount{} shards, \ExpScaleIndexCount{} indexes,
\ExpScaleVersionCount{} append-only version, and \ExpScaleAssetCount{} digest-addressed asset
descriptors spanning Hugging Face, S3, and OCI URIs with local mirrors.
It also checks that the manifest includes a world-lineage index, an asset-digest index, and a
split-manifest shard. We then run a generated catalog benchmark with
\ExpScaleTraceShardCount{} trace shards describing \ExpScaleEpisodeCapacity{} episodes. The
committed report records the measured time for parsing and indexing the generated JSON catalog,
\ExpScaleQueryCount{} partition-pruning queries, digest-cache resolution,
and resolver routing over all asset descriptors. This is catalog-side evidence only, but it makes
the scale claim executable: opening a corpus starts from the manifest and indexes rather than from
recursive storage discovery.
