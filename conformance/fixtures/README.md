# Conformance Fixtures

Two deterministic fixture corpora back the validator and clean-room reader results.

## Committed corpora

- `pilot/` — generated by `tools/run_experiments.py`. Contains 1 valid baseline package
  (`valid/baseline.worldepisode.json`) and 14 invalid packages, each injecting exactly one
  requirement failure. `pilot/manifest.json` maps every fixture file to its
  `expected_requirements` IDs.
- `independent/` — 2 hand-authored invalid fixtures written against the public schema without
  using the generator, listed in `independent/manifest.json`. One fixture expects a single
  requirement failure (`ACTION.002`); the other expects three (`TIME.001`, `WORLD.001`,
  `TRACE.001`), so the two corpora together carry 18 expected requirement instances across
  17 fixtures.

Invalid fixture filenames start with the failing requirement ID, for example
`TIME.001_missing_clock_domain.worldepisode.json` or
`ASSET.002_digest_mismatch.worldepisode.json`.

## Consuming the corpora

- Reference validator: `worldepisode validate <fixture.json>` (or `validate_semantics` from the
  `worldepisode` package).
- Clean-room reader (no `worldepisode` import): `python3 tools/cleanroom_conformance_reader.py`
  runs both corpora against the public schemas and reports recall over the expected requirement
  instances.
- The pytest suite in `tests/` parametrizes over both manifests, so every fixture is exercised by
  `make test`.

## Planned extensions (not yet committed)

Additional valid advanced packages (Gaussian appearance, replay, counterfactual profiles),
lossy-conversion examples with expected conversion reports, and cross-simulator replay fixtures
with tolerance envelopes remain planned; they are tracked as open work and are intentionally not
described as existing evidence.
